## Architecture decision records

Each records the alternatives at their strongest before rejecting them, and the
observable trigger that would make the decision wrong.

| ADR | Decision |
|---|---|
| [001](adr/001-tri-modal-fusion.md) | Fuse three independent feature families rather than train one strong text model |
| [002](adr/002-synthetic-corpus.md) | Use a synthetic, campaign-structured corpus as the primary training data |
| [003](adr/003-black-box-threat-model.md) | Model a decision-based black-box adversary, not a white-box gradient attacker |
| [004](adr/004-sqlite-audit-store.md) | SQLite in WAL mode for the audit trail, behind a repository interface |
| [005](adr/005-occlusion-explanations.md) | Counterfactual occlusion for tree-model attributions instead of SHAP |
| [006](adr/006-abstention-band.md) | Three-way ALLOW / REVIEW / BLOCK rather than a binary decision |
| [007](adr/007-review-queue-state-machine.md) | The review queue as an explicit state machine with object-level authorisation |
| [008](adr/008-in-process-tracing.md) | In-process tracing with W3C Trace Context, no collector required |

## Industry acceptance gates

| Gate | Where it is satisfied |
|---|---|
| Not a CRUD-only portal, dashboard-only submission, copied notebook or API wrapper | An original detection system: 265 engineered features, a four-member calibrated fusion, a 35-transform adversarial suite and an operational review workflow, all implemented here |
| At least one meaningful baseline comparison | Two: B0 (37-rule analyst checklist, no learning) and B1 (TF-IDF + logistic regression). [§7.3](07-evaluation-dossier.md) |
| At least one failure-mode, security or robustness experiment | Several: the adversarial suite and the adaptive attacker, the defence ablation, the modality ablation, PG-HARD, the load test, and the security test suite. [§5.4](05-test-strategy.md), [§7](07-evaluation-dossier.md) |
| Runs from documented setup instructions on a clean machine or reproducible container | [QUICKSTART](../QUICKSTART.md), [§8](08-deployment-guide.md); `docker compose up --build` trains and serves with no downloads |
| Secrets and personal data not committed | `.gitignore`, a CI secret scan, and an audit trail that stores no message content. [§4.8](04-threat-model.md), [§7.15](07-evaluation-dossier.md) |
| Exposes operational evidence: logs, metrics, traces, model monitoring | Structured JSON logs, Prometheus metrics, W3C traces with per-stage timings, Grafana dashboard, alert rules, statistical drift detection. [§2.12](02-architecture.md), [§9.12](09-admin-user-guide.md) |
| AI/analytics projects: leakage checks, reproducible splits, baseline models, explainability/error analysis, documented model or system card | Leakage audit that can fail the build, campaign-grouped splits, dataset fingerprints, two baselines, counterfactual explanations, error analysis, generated model card. [§6](06-data-dictionary.md), [§7](07-evaluation-dossier.md) |
