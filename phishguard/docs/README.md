## Architecture decision records

Each records the alternatives at their strongest before rejecting them, and the
observable trigger that would make the decision wrong.

| ADR | Decision |
|---|---|
| [001](adr/001-tri-modal-fusion.md) | Fuse three independent feature families rather than train one strong text model |
| [002](adr/002-synthetic-corpus.md) | Use a synthetic, campaign-structured corpus as the primary training data |
| [003](adr/003-black-box-threat-model.md) | Model a decision-based black-box adversary, not a white-box gradient attacker |
| [004](adr/004-sqlite-audit-store.md) | SQLite in WAL mode for the audit trail, behind a repository interface |
| [005](adr/005-occlusion-explanations.md) | Counterfactual occlusion for tree-model attributions instead of SHAP |
| [006](adr/006-abstention-band.md) | Three-way ALLOW / REVIEW / BLOCK rather than a binary decision |

## Industry acceptance gates

| Gate | Where it is satisfied |
|---|---|
| Not a CRUD-only portal, dashboard-only submission, copied notebook or API wrapper | An original detection system: 265 engineered features, a four-member calibrated fusion, and a 30-transform adversarial suite, all implemented here |
| At least one meaningful baseline comparison | Two: B0 (37-rule analyst checklist, no learning) and B1 (TF-IDF + logistic regression). [§7.3](07-evaluation-dossier.md) |
| At least one failure-mode, security or robustness experiment | Four: the adversarial suite, the defence ablation (8 arms retrained), the modality ablation (7 combinations), and the security test suite. [§5.4](05-test-strategy.md), [§7](07-evaluation-dossier.md) |
| Runs from documented setup instructions on a clean machine or reproducible container | [§8](08-deployment-guide.md); `docker compose up --build` trains and serves with no downloads |
| Secrets and personal data not committed | `.gitignore`, a CI secret scan, and an audit trail that stores no message content. [§4.8](04-threat-model.md) |
| Exposes operational evidence: logs, metrics, traces, model monitoring | Structured JSON logs with request IDs, Prometheus metrics, Grafana dashboard, alert rules, score-distribution drift signal. [§9](09-admin-user-guide.md) |
| AI/analytics projects: leakage checks, reproducible splits, baseline models, explainability/error analysis, documented model or system card | Leakage audit that can fail the build, campaign-grouped splits, two baselines, counterfactual explanations, generated model card. [§6](06-data-dictionary.md), [§7](07-evaluation-dossier.md) |
